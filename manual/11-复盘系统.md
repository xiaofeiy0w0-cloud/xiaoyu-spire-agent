# 复盘系统

> 建站日期：2026-10-24（用户提议：「也应该有自己完善的复盘系统」）
> 原因：之前只有散文式对局账。写了很多，但**问不出数字**——
> 「我最近 10 局平均死在第几层」「收牌多的局是不是活得更短」这类问题，靠印象答不了。

---

## 〇、一句话

**局内靠清单，局后靠记录，每 5 局靠统计。**
三层都不能少——只做局内会重复犯错，只做局后会写故事但不改，只做统计会知道原因却记不住细节。

---

## 一、局内（打的时候）

读 `00-开打前必读.md`，在**四个节点**各停一下：

| 节点 | 要问自己的一句 |
|---|---|
| **开局选路** | 这张地图有几个火堆/商店/精英？我要走哪条，为什么？ |
| **每场战斗第一回合** | 这场要打几回合？总共会挨多少？我扛得住吗？ |
| **看到奖励面板** | **先看自己的配比**（攻 8~9 / 挡 5~6 / 总数越少越好），再看牌 |
| **站到火堆上** | 敲了这一张，我能不能活过下一场？ |

> ⚠️ 「看到奖励面板先看配比」这条是专门为「宁缺毋滥」设计的。
> 我犯过三次，不是因为忘了规则，是因为**站在奖励界面前只问「这张强不强」**。

## 二、局后（一局打完，30 秒）

**一条命令记完：**

```powershell
python -X utf8 research\sts_log.py add floor=7 cause=精英三哨卫 hp_in=38 `
  deck=15 atk=8 blk=5 rest=1 smith=1 elites=1 shops=0 picked=5 skipped=0 `
  note="关键回合手牌被眩晕堵死，能打出的只有1张"
```

字段见 `sts_log.py` 头部注释。**能一条命令记完才会记**，所以别加太多字段。

**然后才是散文**：把「这局最贵的一课」写进 `40-项目\尖塔-对局账.md`。
散文负责故事和感受，结构化记录负责数字。两者不互相替代。

## 三、每 5 局（统计，看模式）

```powershell
python -X utf8 research\sts_log.py stats
```

它会输出：

- 平均存活层数 / 最深
- **死因排行**（柱状）
- **相关性表**：牌组张数、收牌数、睡觉数、敲牌数、格挡数、攻击数、精英数
  —— 各自和「存活层数」的相关系数
- 火堆总账（睡 vs 敲）
- 终局牌组均值 vs 目标

### 怎么读相关性

```
r > +0.15  ↑  这项多 → 活得久
r < -0.15  ↓  这项多 → 死得早
|r| < 0.15 ·  看不出关系
```

> **⚠️ 20 局以内别下结论。** 样本少的时候相关系数会被单局极端值带歪。
> 它的用途是**指出该往哪看**，不是**证明因果**。

### 真正常用的三问

1. **我的死因集中在哪？**（精英 / Boss / 普通怪 / 事件）
2. **我实际做的和以为做的差在哪？**（→ 见下面第 4 节）
3. **哪个数字离目标最远？**

---

## 四、最重要的检查：「我以为 vs 实际」

**每次统计，都要找一条「原来我以为 X，其实是 Y」。**

这条是整套系统的核心。因为我的失败模式不是「不知道」，
而是**知道 A，做着非 A**。

### 已经抓到的实例

| 我以为 | 实际（统计/查证后） |
|---|---|
| 我知道火堆不该睡觉 | **3 局里睡了 5 次，敲了 5 次**——一半时间在睡 |
| 我的格挡够用（"6 张够"） | 终局均值**挡 4.0**，目标 5~6，**常年偏低** |
| 我的牌组只有 15 张 | 其中 4.4 张是技能/状态牌，**能打架的只有 11.3 张** |
| 我知道「宁缺毋滥」 | 一局从 10 张收到 15 张，**同一个毛病第三次** |
| 火堆「下一站精英就睡」 | **和自己已知的攻略正相反**，用户问「为什么」才发现 |

> 这张表比任何攻略都值钱。**它记录的是我自己的偏差，不是通用知识。**

## 五、改动登记的闭环

每条「我改了什么」要能追到「改完有没有用」。

```
发现偏差 → 改 00-开打前必读 → 之后 5 局看统计里对应的数字有没有变
```

| 改动 | 对应指标 | 改完看什么 |
|---|---|---|
| 奖励面板先看配比 | `picked` / `deck` / `blk` | 牌组张数有没有降下来、格挡有没有补上 |
| 火堆只在「马上要死」时睡 | `rest` / `smith` | 睡:敲 的比例有没有变成 敲 >> 睡 |
| 战斗前算整场 | `hp_in` | 进最后一战的血量有没有变高 |
| 姿态推断器 | — | 进愤怒前有没有算好退路 |

**没对上的指标 = 改动没落地。** 这时候不是"再改一次"，是先查「为什么没落地」。
