# 决策卡：让脑子只做决定

> 她要的原话：「设计一种能让脑子不做记录、而只做决定的打法。不是让我更快，而是让我能把已经算过的放下。」
> 脚本：`tools\card.py`（已能出三行卡，测过真实状态 + 合成战斗）

## 她定的三条规矩

1. **三行以内**
2. **每回合重算，不引用上回合**——不累积，否则又变成她背
3. **算归脚本，判断归她**

## 她补的一条算法定义（重要）

> 「『能挡』不是手牌总格挡，是**这回合 3 点能量最多能挡多少**。四张防御牌但只有 3 费，只能挡 15。」

→ 任何「可挡 / 可打」的数字都必须**受能量约束**，不是把牌面数值相加。

## 现在的三行（已实现）

```
[R3] 我 血48/80 甲0 费3 ‖ 哨卫 62/120 甲0 意图 打24 ; 哨卫 9/120 甲0 意图 打
手牌：Strike(1) Defend(1) Bash+(2) Iron Wave(1)
威胁：共被打24，现有甲0 → 净掉24；敌人合计71血
```

## 还缺什么

- **每个动作的结局**（打多少 / 挡多少 / 掉多少血）：需要卡牌伤害与格挡表（`03-观者卡表.md`、`05-状态数值.md`、`19-战士跟练手册.md`）；
- **能量约束下的最优组合**：不是「全攻 / 全守 / 对半」，而是按费用算出可达的三条最好路线；
- **架势/姿态修正**（观者）、Frail / Weakened 修正（她踩过：看到的 6 实际打 4）。

## 铁律

- 卡片**不写解释、不写上回合、不写建议理由超过半行**；
- 每回合重新读 `C:\sts_bridge\state.json`，不做历史累积；
- 只在开打前给一次；打的过程中她要卡再给，不主动刷屏。

## 2026-10-26 22:07 补丁：会死必须喊（实战补的）

**起因**：用户造假数据实测——我 48/80 血、3 费、两只哨卫（打 24 / 打 12）、手牌 Strike+Defend×2+IronWave、愤怒。
卡片算出「若全守→净掉 57 血」，**48 − 57 = −9，会死，但卡片一声不吭。**

**加了三件**（`tools\card.py`）：

1. **会死必须喊** —— 判据 `净掉 ≥ 当前血`（**不是 `>`**：血打到 0 就是死，不是剩 1）
   ```
   若全守→净掉 57 血 ⚠ 会死（净掉超过血量 48，48 − 57 = −9）；斩杀 22≥71？否；姿态 wrath
   ```
2. **有活路直接给，药水也算进去**（原来只算手牌）
   ```
   活路：Block Potion（+12 挡） → 净掉 45，剩 3 血
   ```
   药水表只收两种能改变这一回合生死的：**Block Potion = +12 挡、Weak Potion = 伤害 ×0.75**。
   其余药水（能量 / 集中 / 抽牌 / 纯伤害）**不猜**——列名字但不进计算。
   药水也救不了就打 `⚠ 没有活路：手上全守仍净掉 57（血 48）`，**不许沉默**。
3. **斩杀别只看总血** —— 总血 71 永远斩不掉，但先杀一只 9 血的只要 9 伤：
   ```
   先杀 Sentry(9) 够，之后每回合少挨 24
   ```

**行数**：基础三行不变；会死时 +1（活路 / 没活路）；总斩杀不成且敌人 ≥2 时 +1（先杀）。最多 5 行。

**验收**（假状态都在 `.tmp\fake_lead_*.json`，命令见下）：

| 用例 | 期望 | 结果 |
|---|---|---|
| 48 血 / 净掉 57 / 无药水 | 报「⚠ 会死」+「没有活路」 | ✓ |
| 同上 + Block Potion | 报活路，剩 3 血 | ✓ |
| 同上 + Weak Potion | 报活路，剩 9 血（72→54） | ✓ |
| 血 60（不该误报） | 不报会死 | ✓ |
| 血 57 == 净掉 57（边界） | **也报**（0 血就是死） | ✓ |
